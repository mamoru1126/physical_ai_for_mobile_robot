# Orin のベンチ（ロボットに載せる前に、エレベーターのタスクを通す）

ロボットに載せる前の Orin（ネットにはつながるが、電源モードを最大にはできない）で、エレベーターのタスクを1回通します。実機（ロボットとエレベーター）の代わりに「ダミーの世界」をつなぎます。VLM・実行系・安全ゲートは本物です。画面（WebUI）で操作して通すことも、自動で通すこともできます。

| 項目 | 状態 |
| --- | --- |
| Orin での通し | まだ（この手順で行う） |
| スクリプトの通し（x86、モックの VLM） | GitHub Actions で、`bench_up.sh` → `bench_e2e.sh` をそのまま動かして PASS。ダミーの世界 → 実行系 → 安全ゲート 2 段 → ダミーの世界の順に、指令が通ることも確かめた（[.github/workflows/elevator-bench.yml](../../.github/workflows/elevator-bench.yml)） |
| arm64（Orin と同じ）でイメージを作る | GitHub Actions で確かめた（中の単体テストも通る） |

## 何が本物で、何がダミーか

| 部品 | ベンチ | ロボットに載せた後 |
| --- | --- | --- |
| VLM | 本物（Orin の vLLM） | 同じ |
| 実行系（計画、判定、指差し、スキル、WebUI） | 本物 | 同じ |
| 安全ゲート（速度の上限と、入力の途絶の監視。Python） | 本物 | 同じ |
| 安全ゲート（点群を見るもの。[safety_gate/](../../safety_gate/)） | 本物（設定はベンチ用） | 同じ（実機用の設定） |
| カメラ（`/camera/compressed`） | **ダミー**: Gazebo で撮った正解つきの画像（`elevator_vlm/samples/`、39 枚）から、ロボットの場所・向きと扉の開きに合うものを流す | USB カメラ |
| ロボット（`/cmd_vel` で動き、`/odom`、`/cloud`、TF を出す） | **ダミー**: 平面の上で動く | ロボット（ROS 1 から橋渡し） |
| エレベーター | **ダミー**: 画面の「エレベーターを呼ぶ」で 1 階の扉が開き、3 階へ行く | 本物 |

つながり:

```text
ダミーの世界 ──カメラ画像・オドメトリ──▶ 実行系 ◀──HTTP──▶ VLM（vLLM）
     ▲                                     │ cmd_vel_raw
     │ /cmd_vel                            ▼
安全ゲート（点群）◀── /vlm_cmd_vel ── 安全ゲート（Python）
     ▲
     └── /cloud・TF（ダミーの世界）
```

- ベンチの ROS 2 は、ドメインを本番（42）と分けて 43 にし、この Orin の中だけで通信します（`ROS_LOCALHOST_ONLY=1`）。同じネットワークにロボットの橋渡しがあっても、ベンチの `/cmd_vel` はロボットに届きません。
- 電源モードが MAXN だと、起動のスクリプトは始めません（電流が足りずに落ちるため）。`jetson_clocks` も使いません。

## 0. 電源モードを確かめる

今のモードを見ます。

```bash
sudo nvpmodel -q
```

`MAXN` と出たら、MAXN ではないモードに切り替えます。AGX Orin 開発キットの JetPack 7.2 では、既定の `MODE_30W` がモード 2 です（一覧は `sudo nvpmodel -q --verbose`）。

```bash
sudo nvpmodel -m 2
```

前に `sudo jetson_clocks` を実行していたら、再起動して元に戻します。

## 1. 起動する

リポジトリを最新にします。

```bash
cd ~/physical_ai_for_mobile_robot
```

```bash
git pull
```

ベンチを起動します。初回は、実行系と安全ゲートのイメージを作り（数分〜十数分）、VLM のサーバを起動します（重みのダウンロードで数十分）。ネットが要ります。

```bash
bash jetson/bench/bench_up.sh
```

小さいモデルで試すときは、モデルを付けて起動します（VLM がまだ動いていないとき）。

```bash
bash jetson/bench/bench_up.sh RedHatAI/Qwen3.5-4B-quantized.w4a16
```

終わると、2つの WebUI の URL が出ます。

| WebUI | URL | 中身 |
| --- | --- | --- |
| 実行系 | `http://<OrinのIP>:8080/` | カメラの映像、計画、実行の状態、ダミーの世界の真値、成否の判定 |
| 安全ゲート | `http://<OrinのIP>:9001/` | 上から見た 10 m 四方の点群と足形、判定（PASS・SLOW・STOP） |

## 2. 画面で通す

同じネットワークの PC のブラウザで、2つの WebUI を開きます。実行系の画面で、次の順に押します。

1. 「計画を作る」を押す。VLM が 3 つの指示を手順に分けます（数秒〜数十秒）。
2. 表示された計画を確かめ、「承認して実行」を押す。ロボットは扉の判定を始めます。
3. 「エレベーターを呼ぶ」を押す。3 秒後に扉が開きます。

うまくいくと、次のように進みます。

| 進み具合 | カメラの映像（ダミー） | 安全ゲート |
| --- | --- | --- |
| 扉が開くのを待つ | 1 階の乗場から見た扉（閉 → 途中 → 全開） | IDLE（止まっている） |
| 開いたと判定し、かごの中を指差して進む | 全開の扉 | PASS か SLOW |
| かごの中で 180 度旋回する | 「この向きの画像はありません」（奥の壁を向いている間） | PASS か SLOW |
| 扉が閉じ、3 階へ行き、扉が開くのを待つ | かごの中から見た扉（閉 → 途中 → 全開、3F の表示） | IDLE |
| 開いたと判定し、乗場を指差して降りる | 3 階の乗場 | PASS か SLOW |

終わると、実行系の画面の「実行」の欄に、真値による成否が出ます（例: `成否の判定（真値）: 成功: 行先階で降りました`）。やり直すときは「初期位置に戻す」を押して、1 からくり返します。

- VLM が遅いと、扉が閉まる前に乗れないことがあります。ダミーのエレベーターは、扉を全開で 15 秒保持します（`BENCH_DOOR_HOLD_S` で変えられる）。間に合わないときは「「開」を押す／離す」を押して、扉を開けたままにできます。
- 止めたいときは「停止」を押します。

## 3. 自動で通す

人が押すのと同じ操作を、WebUI の API で行います。終わると、PASS か FAIL と、通している間の消費電力が出ます。

```bash
bash jetson/bench/bench_e2e.sh
```

VLM に計画を作らせず、用意した計画で判定と指差しだけを試すこともできます。

```bash
BENCH_PLAN_FILE=elevator_vlm/ros2_ws/src/elevator_task/plans/elevator_expected.json bash jetson/bench/bench_e2e.sh
```

結果は `jetson/log/bench_<日時>_<モデル>/` に残ります。

| ファイル | 中身 |
| --- | --- |
| `e2e.txt` | 通したときの経過 |
| `summary.json` | 成否、手順ごとの結果、真値による判定 |
| `analysis.txt` | VLM の答えと真値の突き合わせ、応答時間 |
| `events.jsonl` | VLM への問いと答え、実行の経過（使ったダミーの画像の名前つき） |
| `power.txt`、`tegrastats.log` | 通している間の消費電力、GPU の使用率 |
| `env.txt` | 電源モード、モデル、イメージ |
| `*.jpg` | 要所のカメラの映像 |
| `bench.log`、`safety_gate.log`、`vlm.log` | 各コンテナのログ |

## 5. 止める

ダミーの世界・実行系・安全ゲートを止めます（VLM は動かしたまま）。

```bash
bash jetson/bench/bench_down.sh
```

VLM のサーバも止めるときは、`--all` を付けます。

```bash
bash jetson/bench/bench_down.sh --all
```

## 6. ロボットに載せる前に: ネットなしで動くかを確かめる

ロボットに載せるとネットにつながらないので、要るものがすべて Orin に入っているかを確かめます。VLM を、ネットに問い合わせない設定で起動し直して、もう一度通します。

```bash
bash jetson/vlm_down.sh
```

```bash
VLM_OFFLINE=1 bash jetson/vlm_up.sh
```

```bash
bash jetson/bench/bench_e2e.sh
```

PASS すれば、VLM の重みとイメージ、実行系と安全ゲートのイメージは、すべて Orin に入っています。ロボットに載せた後も、VLM は `VLM_OFFLINE=1` を付けて起動します。

## ベンチで分かること、分からないこと

| 分かること | 分からないこと |
| --- | --- |
| 電源モードを抑えた Orin で、VLM の応答が間に合うか（応答時間） | 本物のカメラ・照明・エレベーターでの、VLM の見分けの正しさ |
| 通している間の消費電力（電源が持つか） | ロボットの電源での消費電力 |
| VLM・実行系・安全ゲート 2 段・WebUI が、実機と同じトピックでつながること | 実機の動き（オドメトリのずれ、すべり） |
| ネットなしで起動できること（6.） | 実機の点群での、安全ゲートの判定 |

- ダミーのカメラの画像は、決まった位置（乗場の待機位置、かごの中央、かごの扉の近く）から撮ったものだけです。ロボットが進んでも、同じ場所なら同じ画像のままです。そのため、ベンチの設定では、走行中に指差しをやり直す機能（`skills.repoint_period_s`）を切っています。
- カメラの取り付けと足形は、画像を撮ったシミュレーションのロボットの値にしてあります。ロボットに載せるときは、実機の値の設定を使います。

## うまくいかないとき

| ようす | 見るところ |
| --- | --- |
| 「電源モードが MAXN です」で始まらない | 0. の手順でモードを切り替える |
| MAXN ではないのに Orin が落ちる | 小さいモデル（4B）にする: `bash jetson/bench/bench_down.sh --all` のあと `bash jetson/bench/bench_up.sh RedHatAI/Qwen3.5-4B-quantized.w4a16`。それでも落ちるなら、もっと低い電源モードにする |
| 扉が閉まる前に乗れない | `BENCH_DOOR_HOLD_S=30 bash jetson/bench/bench_up.sh` で、扉を開けておく時間を延ばす。画面の「「開」を押す／離す」でもよい |
| 安全ゲートの画面が STOP のまま、ロボットが動かない | 安全ゲートの画面の理由（「TF がありません」「点群が途切れました」など）を見る。`docker logs elevator-bench-gate` |
| 「ポート 8080（9001）を別のプログラムが使っています」 | 9001 なら、実機用の安全ゲートのサービスを止める: `sudo systemctl stop safety-gate` |
| イメージを作るところで止まる | ネットとプロキシの設定を確かめる。作り直すときは `BENCH_REBUILD=1 bash jetson/bench/bench_up.sh` |
| 実行系の画面で「VLM サーバに接続できません」 | `docker logs elevator-vlm` で、VLM のサーバが起動し終わっているかを見る |
