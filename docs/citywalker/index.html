CityWalker の解説と Jetson Orin での構成例

まとめ

  1. ネット上の街歩き動画 2,000 時間超で学習した、目標点へ向かう走行モデルである。動画に行動のラベルはないので、視覚オドメトリで作る。
  2. 言語は扱わない。入力は過去の画像5枚、過去の位置5点、目標の位置1点で、出力は未来の経由点5つと到着の判定である。
  3. 実機の成功率は 77.3% で、右左折で既存手法との差が大きい。ViNT（微調整あり）は 57.1%、NoMaD（ゼロショット）は 42.9% だった。
  4. モデルは約 2.14 億パラメータで、7B 級の VLA よりかなり小さい。ただし論文に搭載計算機と推論速度の記載はなく、Jetson Orin での速度は実測が要る。
  5. 位置の入力が必須である。地図は要らないが、過去の軌跡と目標の相対位置は要る。著者も GPS の誤差に弱いことを課題に挙げている。

1何を解決したいか

人は知らない街でも、地図アプリが示す経由点をたどって目的地に着く。アプリが教えるのは大まかな道順だけで、経由点の間を歩くには、人混み、横断歩道、信号、障害物への対応が要る。論文はこの部分を「都市での身体性ナビゲーション」と呼び、未解決の問題だとする（Sec. 1）。

既存の強化学習や模倣学習は、静的な環境や管理された環境では動くが、都市の複雑さには届かない。遠隔操作で集めた既存のデータセットにも、こうした場面は十分に含まれていない（Sec. 1）。

2全体像

考え方は単純で、人が街を歩く動画を大量に集め、模倣学習の教師にする。課題は、動画に「どう動いたか」のラベルがないことである。VLM に行動ラベルを作らせる既存の方法は費用がかかり、大規模にしにくい。論文は、既製の視覚オドメトリが出す粗いラベルで十分だと主張する（Sec. 1）。

問題設定は、目標の座標を与えて走らせるポイントゴール型に近い。目標は地図アプリから得る経由点を想定している（Sec. 3.1）。

4学習の工夫

行動ラベルの作り方

視覚オドメトリには DPVO を使う。動画全体の軌跡は誤差がたまるので、短い区間の相対姿勢だけを使う。ほかの視覚オドメトリでもよいとしている（Sec. 3.3）。

縮尺の扱い

単眼の動画からは実寸が分からない。そこで、行動を軌跡の中の平均の歩幅で割って正規化する。GNM と同じやり方である。実機で使うときは、そのロボットの歩幅を掛けて戻す（Sec. 3.3）。

6評価と結果

実機

機体は四脚の Unitree Go1。出力の経由点は、ViNT と同じ PD 制御で速度指令に変える。目標は 50〜100 m 先に置き、条件ごとに 8〜14 回試した。目標から 5 m 以内で到着と判定できれば成功とする（Sec. 4.2）。

7著者が述べている課題

  • GPS の誤差に弱い。位置の扱いが単純で、大きな位置の誤りを想定していない（Sec. 5）。
  • 迂回の場面が弱い。学習に使った動画に迂回の場面が少ないためとしている（Sec. 4.2）。

8論文から読み取れること

ここからは論文の記述ではなく、この資料の見解である。

  • 言語指示の課題には、単体では使えない。「扉が開いたら入る」のような条件は入力できない。使うなら、VLM が決めた目標点まで走る下位の走行器としてである（エレベーターの検討の「VLA を後から足す道」と同じ位置づけ）。
  • 自己位置が要る。地図は要らないが、過去5点の軌跡と目標の相対位置は要る。短い距離ならオドメトリで代用できる見込みがあるが、論文は GPS を前提にしており、確かめられていない。
  • 車輪型と屋内は検証の外である。実機は四脚、場所は屋外の歩道である。車輪型では歩幅の換算を決め直す必要があり、微調整も要ると見ておく。
  • 大きさは扱いやすい。2.14 億パラメータで、画像の符号化器は固定である。7B 級の OmniVLA と比べると、ロボットの上で動かす負担はずっと小さい。
  • 障害物回避は学習まかせである。距離センサを使わない。安全の層は別に要る。

9Jetson Orin での構成例

論文に搭載計算機と推論速度の記載はない。以下はこの資料の設計案で、数値は目安である。

ノード役割頻度の目安
camera_driverRGB 画像を出す10 Hz
pose_sourceGPS かオドメトリから、ロボット基準の過去5点と目標の位置を作る10 Hz
frame_buffer画像5枚と位置5点を、学習時と同じ間隔で保持する学習時の間隔
citywalker_infer経由点5つと到着の判定を出す。TensorRT、FP162〜5 Hz（要実測）
waypoint_follower歩幅を掛けて実寸に戻し、PD 制御で速度指令にする20〜50 Hz
safety_gate速度の上限。推論が途絶えたら停止50 Hz
goal_manager到着の判定で、次の目標点へ切り替える切替時

設計の要点

  • 画像の符号化器と本体を分けて変換する。DINOv2 は重みが固定なので、単独で TensorRT にでき、5枚をまとめて流せる。新しい1枚だけを符号化し、残りの4枚は結果を使い回せば、計算は約5分の1になる。
  • 目標点の与え方を先に決める。屋外は GPS の経由点、屋内はオドメトリ座標での相対目標になる。どちらも、ロボット基準の相対位置に直してから渡す。
  • 画像の間隔を学習時に合わせる。間隔がずれると、過去の位置の並びと歩幅の正規化が学習時と合わなくなる。
  • 歩幅の換算を機体に合わせる。車輪型では「1ステップで進む距離」を、巡航速度と画像の間隔から決める。
  • 推論が遅れても走れるようにする。経由点はオドメトリ座標で保持し、次の推論が届くまで同じ経由点を追う。

確かめる順序

  1. 公開コードの設定で、画像の間隔と解像度、重みの公開の有無を確かめる。
  2. Orin の上で変換し、推論1回の時間を測る。
  3. 手持ちの走行記録を流し、出力の経由点が実際の軌跡に沿うかを机上で見る。
  4. 低速で実機を走らせる。合わなければ、走行記録で微調整する。
